# Cyber Adventure Challenges

Each theme is now set up to work independently with a sibling `Docker-TCP-Switchboard` folder. That means someone can download:

- `Docker-TCP-Switchboard/`
- `IPN Theme/` or `RowdyCon Theme/`

and bring the stack up from inside that theme folder without a repo-wide theme selector.

## Use one theme by itself

Read the README inside the theme you want to run:

- [IPN Theme/README.md](IPN%20Theme/README.md)
- [RowdyCon Theme/README.md](RowdyCon%20Theme/README.md)

Both themes now include the same local workflow:

```bash
cd "<theme folder>"
./labctl.sh up
```

That local script builds the theme images, starts the theme support stack, generates the switchboard config, and starts the switchboard container.

## Theme generator

The repo also includes a maintainer tool in [theme-generator/](theme-generator/) for creating a brand-new theme from one existing baseline.

Its purpose is different from `labctl.sh`:

- `labctl.sh` is for running an existing theme
- `theme-generator/generate_theme.py` is for creating a new theme folder from a baseline theme with a small config file

The generator is meant to reduce the manual work of making a third theme by rewriting the repeated theme-specific pieces across the challenge content, such as:

- theme names and event branding
- flag prefixes
- usernames and user-prefix naming
- support stack network names and service names
- website directory/domain references
- Windows evidence directory names and mount paths

It also runs an audit after generation so leftover IPN or RowdyCon markers are easier to catch before publishing a new theme.

Read [theme-generator/README.md](theme-generator/README.md) for step-by-step usage.

## Theme structure

Each theme folder follows the same high-level layout:

- `Crypto/`
- `Linux/`
- `Windows/`
- `Hack/`
- `CTFd/` or a CTFd backup zip
- `labctl.sh`
- `README.md`

In practice, the theme changes are mostly made in the per-challenge Dockerfiles, challenge scripts, mission text, usernames, flags, websites, and the Windows evidence dataset.

## Editing an existing theme

If you want to change the content of an existing theme without changing its identity, these are the main places to look:

- `Crypto/Dockerfile` and the `crypt*.sh` scripts:
  This is where the crypto usernames, passwords, shells, and challenge flow live.
- `Linux/*/Dockerfile` plus any helper files in those folders:
  This is where Linux usernames, flags, file names, seeded artifacts, and challenge-specific logic live.
- `Windows/*/Dockerfile`, `profile*.ps1`, and `scripts/`:
  This is where PowerShell behavior, usernames, flags, evidence locations, and scheduled-task style logic live.
- `Hack/Box 1/docker-compose.yml`:
  This defines the support containers and internal challenge networks used by the hacking boxes.
- `Hack/Box3/`:
  This usually contains the cloned website content, wordlists, nginx config, and the web-enumeration challenge text.
- CTFd backup zip or `CTFd/` content:
  This is where scoreboard-facing challenge names, descriptions, hints, files, and category presentation are managed.

## Creating a new theme

If you want a third theme that is not based on IPN or RowdyCon, the simplest path is:

1. Copy one existing theme folder and rename it.
2. Update the challenge content inside that copied folder.
3. Update the small set of bootstrapping files that still carry theme-specific names and paths.

The most important files to change are below.

### 1. Theme bootstrap

Edit `labctl.sh` in the new theme folder.

This file is what makes `./labctl.sh up` work, and it currently detects the theme by looking for the Windows evidence directory name. You should update:

- `detect_theme()`:
  Change the evidence directory check, theme slug, support project name, hack network names, and Windows evidence mount path.
- `WINDOWS_EVIDENCE_HOST_DIR`:
  Point this at the evidence directory you want mounted into Windows box 3.
- `WINDOWS_EVIDENCE_CONTAINER_DIR`:
  Keep or change the mount point used inside the container if your new theme uses a different name.

The image tag names generated by `image_name()` do not need to match IPN or RCC, but they should stay consistent for the whole theme.

### 2. Hack support stack and networks

Edit `Hack/Box 1/docker-compose.yml` in the new theme folder.

This is where you should update:

- Docker network names such as `hack_ipn1_net` or `hack_rcc1_net`
- The web service name if you want it renamed
- The website volume paths if the Box 3 website folder name changes
- Any seeded service names, ports, or content that are meant to reflect the new theme

Keep the network names here aligned with the values used in `labctl.sh`, because the switchboard-generated config connects the hack boxes to those exact networks.

### 3. Usernames, passwords, flags, and challenge text

These are spread across the challenge folders.

Typical files to edit:

- `Crypto/Dockerfile`
- `Linux/*/Dockerfile`
- `Linux/*/*.sh`
- `Linux/*/*.c`
- `Windows/*/Dockerfile`
- `Windows/*/*.ps1`
- `Windows/*/scripts/*.sh`
- `Hack/*/Dockerfile`
- `Hack/*/mission*.txt`
- `Hack/*/solution.txt`

This is where you change:

- SSH usernames
- passwords and flags
- seeded filenames
- challenge prompts and instructions
- any hardcoded in-world organization names

### 4. Websites and theme assets

If the hacking track includes a themed website, update the content under `Hack/Box3/`.

Examples:

- static site directory such as `ipn_website/` or `rcc_website/`
- `nginx-autoindex.conf`
- wordlists or mission text tied to the site

If you rename the website folder itself, also update the matching volume path in `Hack/Box 1/docker-compose.yml`.

### 5. Windows evidence data

If your Windows persistence challenge uses a different evidence set, update:

- the evidence directory under `Windows/box3_persistence/`
- any scripts that reference files inside it
- `labctl.sh` so the generated switchboard config mounts the correct host directory

The evidence directory name is one of the places the current theme-local bring-up logic depends on, so this step matters for startup, not just challenge flavor.

### 6. CTFd content

If you want the new theme to have its own scoreboard import, create or update a separate CTFd backup for that theme.

That is where you would change:

- challenge names
- descriptions
- hints
- tags
- attached files
- theme branding shown to players

## Minimum files to update for a brand-new theme

If you are making a new theme and only want the shortest checklist needed to get it running, update these first:

- `<New Theme>/labctl.sh`
- `<New Theme>/Hack/Box 1/docker-compose.yml`
- `<New Theme>/Windows/box3_persistence/` evidence directory and related scripts
- any challenge Dockerfiles or scripts where usernames, flags, or organization names still reference the old theme

## Notes

- The challenge content is unchanged.
- The switchboard is now containerized instead of relying on a host Python venv.
- The IPN support compose stack no longer relies on absolute host paths for the web content mount.
- CTFd backups remain in the repo, but CTFd restore is still separate from the challenge-stack bring-up flow.
